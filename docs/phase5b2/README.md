# Phase 5B-2: 원격 GPU 자동 연결 (Modal 서버리스 GPU)

> 작성 2026-11-18. 상태: **코드 구현과 GPU 없는 검증 완료.** 2026-11-18 사용자가 Modal에 가입하고 토큰을 발급했으며, 승인을 받아 **`object-magic-studio-gpu` 앱을 배포**했습니다.
> - 배포 시간 6분(첫 이미지 빌드 포함)
> - torch 2.14.1+cu130 설치, 체크포인트 SHA-256 `OK`
> - **실제 T4 점검 통과** (2026-11-18, 아래 [실제 T4 측정](#3-1-실제-t4-측정-modal-2026-11-18))
> - **브라우저 전체 흐름 확인 완료**: 실제 720p 영상, 클릭 → 289프레임 추적 → MP4 → 취소 ([3-2](#3-2-브라우저-전체-흐름-실제-modal-t4-2026-11-18))

목표: 웹앱에서 클릭하거나 **Track**을 누르면 원격 GPU에서 SAM 2.1이 실행되고, 결과가 자동으로 돌아와 기존 효과 미리보기와 MP4 내보내기로 이어집니다. Colab ZIP을 옮길 필요가 없습니다.

## 1. 구조

```
브라우저 ──HTTP──> 로컬 FastAPI (세션·프레임·효과·MP4·작업 상태·예산)
                    │  backend="local"  → 기존 로컬 CPU 모델 (변경 없음)
                    │  backend="remote" → RemoteGpuService
                    │                       └ Transport ─ Modal SDK (토큰 인증) ─> Modal GPU 컨테이너 (T4)
                    │                                                              └ GpuWorker
                    │                                                                 ├ Sam2Engine (모델 1개)
                    │                                                                 ├ Sam2ImageService (분할)
                    │                                                                 ├ VideoTracker (추적)
                    │                                                                 └ FeatureCache (분할·추적이 공유)
                    └ 추적 결과(마스크 PNG) → sessions/<id>/tracks/<job>/masks → 기존 미리보기·내보내기
```

### 요구사항별 구현

| 요구사항 | 구현 |
|---|---|
| 1. 기존 SAM 2.1 Tiny fp16 코드 재사용 | 워커는 `Sam2Engine`·`Sam2ImageService`·`VideoTracker`·`CudaRuntime(fp16)`를 그대로 씁니다. Modal 이미지에는 `backend/app`을 그대로 넣고, 모델은 같은 SAM 2 커밋과 같은 체크포인트(SHA-256 검증)를 씁니다. |
| 2. 로컬 FastAPI와 원격 추론 분리 | 원격은 분할·추적만 합니다. 세션, 효과, 내보내기, 작업 API는 로컬이 맡습니다. 원격 작업은 별도 큐(`remote`)에서 돌아서 로컬 CPU 작업과 서로 기다리지 않습니다. |
| 3. 영상·클릭 좌표 전달 | 원본 MP4를 SHA-256과 함께 보냅니다. 원격이 서버와 같은 `extract_frames`로 프레임을 뽑고, **크기와 프레임 수가 로컬과 같은지 확인**합니다. 좌표는 로컬과 같은 규칙으로 원본 픽셀 좌표로 바꿔 보냅니다. |
| 4. 300프레임 결과 자동 회수 | 진행 이벤트를 스트리밍하고, 마지막에 프레임별 마스크 PNG를 받습니다. 프레임 번호 연속성, 개수, 해상도를 확인한 뒤 저장합니다. 한도는 `OMS_REMOTE_MAX_FRAMES=300`입니다. |
| 5. 효과 미리보기·MP4 그대로 | 받은 결과를 로컬 추적 결과와 같은 위치와 형식으로 저장합니다. 그래서 `/tracks/{id}/masks`, `render-frame`, `/export`를 수정 없이 씁니다(테스트로 확인). |
| 6. 진행·실패·취소 | 진행률과 메시지를 표시합니다(`Remote GPU · Frame 23/30 …`). 원격 오류 코드는 그대로 전달합니다(`gpu_oom`, `busy`, `validation`, `remote_unavailable`, `remote_failed`, `budget_exceeded`). **취소 버튼을 누르면 즉시** Modal Dict 플래그를 켜고(콜드 스타트 중에도), 이미 추적한 프레임은 유지합니다. 로컬 CPU와 같은 동작입니다. |
| 7. 인증·업로드 제한·임시 파일·비용 | 아래 [보안과 비용 제어](#4-보안과-비용-제어) |
| 8. 기존 모드 유지 | 로컬 CPU는 화면의 **Local CPU**를 고르거나 `OMS_REMOTE`를 지정하지 않으면 됩니다. Colab ZIP 방식(5B-1)도 변경 없이 그대로 씁니다. 원격이 실패해도 **로컬로 몰래 바꾸지 않고**, 오류 메시지에서 Local CPU로 전환하라고 안내합니다. |
| 9. 기존 테스트 유지 + GPU 없이 검증 | 아래 [검증](#3-gpu-없이-한-검증) |

### 분할·추적이 같은 모델과 임베딩을 공유하는 방법

- **모델 1개**: 컨테이너당 `Sam2Engine` 하나입니다. 영상 예측기와 이미지 예측기가 가중치를 공유합니다(기존과 같음). `max_containers=1`로 두어 모든 요청이 같은 컨테이너, 같은 모델로 갑니다.
- **임베딩 재사용** ([features.py](../../backend/app/inference/features.py)):
  1. 첫 클릭 때 해당 프레임을 **영상 예측기와 같은 전처리**로 한 번 인코딩해 `FeatureCache`(최근 2프레임)에 넣습니다.
  2. 분할은 그 백본 출력으로 이미지 예측기의 내부 특징을 채웁니다. `set_image`의 인코딩 이후 단계와 같은 계산입니다.
  3. 추가 클릭은 디코더만 실행합니다. 다른 프레임을 봤다가 돌아와도 캐시에서 가져옵니다.
  4. **Track**을 누르면 같은 특징을 영상 예측기의 `cached_features`에 미리 넣습니다. 그래서 `init_state`·`add_new_points`가 프롬프트 프레임을 다시 인코딩하지 않습니다.
- 로컬 CPU 모드의 분할은 기존 `set_image` 경로를 그대로 씁니다(동작 변경 없음).

## 2. 사용 방법

화면 오른쪽 **Select object** 패널 맨 위에서 **Remote GPU · T4 / Local CPU**를 고릅니다. 원격이 설정되어 있으면 기본값은 Remote GPU입니다.
- Remote GPU를 고르면 처리 방식(fp16), 상태, 오늘 사용량과 이번 달 추정 비용, **Start GPU**(미리 켜기) 버튼이 보입니다.
- 추적 프레임 수 아래에 원격 기준 예상 시간과 **추정 비용**이 표시됩니다.
- 분할·추적 측정값에는 원격 여부, 업로드 시간, 임베딩 재사용 여부, 추정 비용이 함께 나옵니다.
- 상단 배지: `SAM 2.1 · CPU`(로컬) 옆에 `Remote T4 · in use`가 나옵니다.

서버 실행:
```powershell
cd backend
$env:OMS_REMOTE = "modal"            # 원격 GPU 사용 (지정하지 않으면 로컬 CPU 만)
.venv-sam2\Scripts\python -m uvicorn app.main:app --port 8000
```
GPU 없이 원격 경로 전체를 시험하려면 `$env:OMS_REMOTE = "inprocess"`로 실행합니다(로컬 모델이 원격 워커 역할을 합니다). 이 모드의 사용량은 별도 파일에 기록되며, 표시되는 비용은 실제로 청구되지 않는 계산값입니다.

| 환경 변수 | 기본값 | 의미 |
|---|---|---|
| `OMS_REMOTE` | (빈 값) | `modal` / `inprocess` / 빈 값 = 원격 없음 |
| `OMS_REMOTE_MAX_FRAMES` | 300 | 원격 추적 1회 최대 프레임 |
| `OMS_REMOTE_MAX_UPLOAD_MB` | 100 | 원격으로 보내는 영상 최대 크기 |
| `OMS_REMOTE_DAILY_GPU_SECONDS` | 1800 | 하루 추정 청구 시간 한도 (30분 ≈ $0.37), 0 = 없음 |
| `OMS_REMOTE_MONTHLY_USD` | 5 | 한 달 추정 비용 한도, 0 = 없음 |
| `OMS_REMOTE_COST_PER_S` | 0.000208 | 초당 단가 (T4 + CPU 2코어 + 메모리 8GiB) |
| `OMS_REMOTE_IDLE_S` / `OMS_MODAL_IDLE_S` | 120 | 마지막 호출 뒤 컨테이너 유지 시간 (두 값을 같게) |
| `OMS_REMOTE_COLD_START_S` | 25 | 콜드 스타트 추정치 (실측 19.1초 + 여유) |
| `OMS_MODAL_GPU` | T4 | 배포할 GPU 종류 |

새 API: `POST /api/remote/warmup`(컨테이너 미리 켜기, 요금 발생)이 추가됐습니다. `segment`·`propagate` 요청 본문에는 `backend: "auto" | "local" | "remote"`가 추가됐고, `/api/health`의 `remote`에 설정·상태·사용량이 나옵니다. **상태 조회만으로는 GPU를 켜지 않습니다.**

### 3-1. 실제 T4 측정 (Modal, 2026-11-18)

`scripts/remote_smoke.py --provider modal --frames 300`을 실행했습니다. 합성 영상(640×360, 300프레임)을 썼고, 로그는 `realworld/work/modal_smoke*.log`에 있습니다.

| 항목 | 결과 |
|---|---|
| **콜드 스타트** (컨테이너 시작 + 모델 로드 + 첫 호출) | **19.1초** (예상 45초보다 짧음) |
| 컨테이너가 켜져 있을 때 첫 호출 (새 클라이언트의 연결 준비 포함) | 5.6초 |
| 영상 업로드(0.3MB) + 원격 프레임 추출(300장) | 2.1~2.7초 (720p 영상은 파일이 더 커서 더 걸림) |
| 클릭 분할 왕복 | **약 0.9~1.1초** (T4 인코더 121ms, 나머지는 네트워크와 Modal 호출 오버헤드) |
| 추가 클릭 | 임베딩 캐시 사용 (인코딩 0회) |
| 정확도 (정답 원 대비) | 분할 IoU 0.982, **300프레임 추적 평균 0.984 / 최저 0.969** |
| **300프레임 추적** | **67.1초** (GPU 프레임당 **165ms** ≈ 6fps, Colab T4 191~212ms보다 빠름), 최대 GPU 메모리 889MB |
| 임베딩 재사용 | 추적이 분할 때 계산한 프롬프트 프레임 특징을 재사용함 (`promptFeaturesReused: True`) |
| 진행률 스트리밍 | 진행 이벤트 202개 수신 |
| 이번 점검 추정 비용 | 1회 약 $0.043 (대기 120초 포함). 실패한 첫 시도를 포함하면 약 $0.09 이하. 실제 청구액은 Modal 대시보드에서 확인 |

**실행 중 생긴 문제 1건**
- 첫 시도에서 분할까지는 정상이었습니다.
- 추적 스트림이 연결을 새로 여는 순간, 이 PC의 DNS 조회가 한 번 실패했습니다(`getaddrinfo failed`).
  - 직후 같은 주소를 조회하면 정상이었으므로 **일시적인 네트워크 문제**로 판단했습니다. 다시 실행하자 통과했습니다.
- 이 오류는 원래 "원격 실패(`remote_failed`)"로 분류되었는데, 이제 "연결 불가(`remote_unavailable`)"로 분류하고 다시 시도하라고 안내하도록 고쳤습니다.
- 스트림이 끊기면 그 추적 결과는 받지 못합니다. 다시 실행하면 원격에서 처음부터 다시 추적하므로 비용이 한 번 더 듭니다.

### 3-2. 브라우저 전체 흐름 (실제 Modal T4, 2026-11-18)

서버를 `OMS_REMOTE=modal`로 실행하고, 실제 영상 `01_dog.mp4`(1280×720, 30000/1001, 289프레임, AAC 오디오, 1.7MB)를 썼습니다. 스크린샷은 [browser_modal.jpg](browser_modal.jpg)입니다(라이선스가 명시되지 않은 데모 영상이라 로컬에만 있음).

## 4. 보안과 비용 제어

**인증**
- 공개 웹 엔드포인트를 만들지 않습니다. 로컬 서버가 **Modal SDK와 토큰**(`~/.modal.toml` 또는 `MODAL_TOKEN_ID/SECRET`)으로만 호출하므로, 토큰이 없는 사람은 GPU를 쓸 수 없습니다.
- 토큰은 워크스페이스 권한이므로 저장소에 넣지 마세요(`.gitignore` 대상 아님 → 홈 폴더에만 둡니다).
- 로컬 서버는 `127.0.0.1`에서만 열립니다. 네트워크에 공개한다면 별도 API 인증이 필요합니다(현재 범위 밖). 예산 한도가 피해를 제한합니다.

**업로드 제한**
- 로컬 업로드 검증(10초, 해상도, 100MB)을 통과한 영상만 보냅니다(`OMS_REMOTE_MAX_UPLOAD_MB`).
- 원격은 SHA-256 일치, 크기, 같은 검증 코드로 다시 확인합니다.
- 프롬프트 좌표는 범위·개수(≤64)·양성 점 포함 여부를, 프레임은 300 이하인지 확인합니다.

**임시 파일**
- 원격에는 **컨테이너 로컬 디스크(/tmp)에만** 저장하며, 영구 Volume은 없습니다. 원본 MP4는 프레임 추출 직후 지웁니다.
- 영상은 최근 3개까지만 두고(LRU), 세션을 삭제하면 원격에서도 지웁니다.
- 컨테이너가 꺼지면(마지막 호출 120초 뒤) 모두 사라집니다. 추적 작업 폴더는 결과를 보낸 즉시 지우고, 취소 플래그도 작업이 끝나면 지웁니다.

**사용량·비용**
- Modal 설정은 `min_containers=0`(사용하지 않을 때 0원), `max_containers=1`(GPU 동시 1대), `scaledown_window=120초`, 호출당 `timeout=600초`입니다.
- 로컬 예산 한도는 하루 30분, 한 달 $5(추정치 기준)이며, 넘으면 `budget_exceeded`(429)로 막습니다.
- 추정 방식: 콜드 스타트 + 호출 시간 + 대기 시간, 동시 호출의 중복은 제외합니다. 실제 청구액의 기준은 Modal 대시보드입니다.
- **Modal 워크스페이스 예산(Starter 플랜에서 설정 가능)을 함께 걸어 두는 것을 권장합니다.**
- 개인정보: 원격을 선택하면 영상 프레임이 Modal(미국 클라우드)로 전송됩니다. 민감한 영상은 Local CPU를 쓰세요.

## 6. 실제 GPU 연결에 필요한 사용자 작업 (승인 후)

1. **Modal 가입** (https://modal.com, Starter 플랜): 결제 수단 등록이 필요한지는 가입 화면에서 확인해 주세요.
2. **워크스페이스 예산 설정**: Settings → Usage/Billing에서 월 한도를 겁니다(예: $5~10).
3. **토큰 발급** (로컬 PC에서, 브라우저 로그인):
   ```powershell
   cd backend
   .venv-sam2\Scripts\modal token new
   ```
4. 여기까지 해 주시면 제가 이어서 진행하겠습니다(각 단계 전에 다시 확인을 받습니다):
   - `modal deploy remote_gpu/modal_app.py`: 이미지 빌드(첫 회 수 분), 배포 자체는 GPU 요금 없음
   - `python scripts/remote_smoke.py --provider modal --frames 300`: 실제 T4로 연결·정확도·속도·콜드 스타트 측정 (≈ $0.05)
